# Vox的命名规范 & 规定

## 说明
命名规范只是让团队/用户之间协作变得流畅，不是强制规定。毕竟每个公司或个人都有自己喜欢的规范，命名是自由的，规范只是让他人使用能更好的使用

## 规范
| 类型 | 规范 | 示例 |
|---|---|---|
| 普通变量 | 小驼峰 | `idiotLike` |
| 常量 | 全大写 + ‘_’分割 | `KEY_W` |
| 类 | 大驼峰 | `EntityManager` |
| 普通函数| 小驼峰 | `isIdiot` |
| 私有变量 | ‘_’ + 小驼峰 | `_isIdiot` |
| 转换类型函数 | 全大写 + 无分隔 + 字数在 2~8 以内，使用“3”代替“转换”词| `RGB3HEX` |
| 文件名 | 小驼峰 | `playerMove.v` |
| 构造函数 | 构造函数`_init_`应以`self`作为返回值 | `self _init_()` |
| 异常类 | `XxxException` | `IdiotLikeException` |

## 规定 / 约定
| 类型 | 规定 / 约定 | 示例 | 补充 |
|---|---|---|---|
| 初始化文件夹文件 | `_init_.v` | `_init_.v` | - |
| 类的“魔法方法” | `_xxx_` | 构造函数`_init_` | 详情看[魔法方法](基础语法.md#魔法方法) |
| GUI 项目 | 在第一次执行`vox run "file.v" --window`以复制一些重要的`.dll`文件 | `vox run "guiTest.v" --window` | - |
| GUI 项目 | 以后执行`vox run "file.v" --gui`以编译成没有cmd窗口的程序 | `vox run "guiTest.v" --gui` | - |

每个项目的主文件开头都必须导入`Code`库，否则直接`SyntaxException`！  
尽量不要动标准库里的任何文件，如果应此发生错误，请撤回或重新下载。因为每个文件都有可能与其他文件关联  
`foreach`多变量最好不要超过4个同时循环，否则可读性会不好  
不要滥用`any`类型，因为他将不会触发编译器的静态编译期检查，但IDE可以（测试）。`any`类型本身不是真正意义上的“动态”，他只是一个能装下任何类型的一个类型，因此您不需要为`any`的性能担忧，您只需要为编译时长担忧就行了😜  ——
